# 性能基准（合成数据）

> 日期：2026-11-25  
> 结论只代表**本机、本版本、合成语料**的本地流水线，不代表真实教材上的检索质量。

## 环境

- Windows 11 10.0.26300 x64
- Intel Core Ultra 9 285H / 64 GB（基准未使用 GPU）
- Python 3.12.11（uv 虚拟环境），SQLite 内置 FTS5 + jieba 预分词
- 数据目录位于 E 盘本地 SSD

## 方法

`benchmarks/run_benchmark.py` 生成含 20 个循环专题、每页唯一 `PAGEMARKn` 标记、
每 25 页一个书签章节的合成 PDF，然后完整执行：

1. 递归扫描 → PDF 解析（pypdfium2 + pdfplumber 坐标）→ 结构感知切分 → FTS5 索引；
2. 20 个唯一标记查询（`PAGEMARKn`）核对 Top-1 是否落在对应页；
3. 5 个专题查询（中文概念）计算 Recall@5（Top-5 是否命中该专题任一页）；
4. 记录检索 P50/P95、数据目录大小。

未配置 Embedding / Reranker / LLM，因此是 **BM25-only** 路径；向量召回与精排的延迟未计入。

## 结果

| 档位 | PDF 页数 | 索引耗时 | 解析+索引速度 | 文本块 | 索引块 | 检索 P50 | 检索 P95 | 标记 Top-1 | 专题 Recall@5 | 数据目录 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| S | 500 | 4.8 s | 105 页/秒 | 1,000 | 500 | 3.9 ms | 9.3 ms | 100% (20/20) | 80% (4/5) | 14.0 MB |
| M | 5,000 | 43.2 s | 116 页/秒 | 10,000 | 5,000 | 21.4 ms | 71.0 ms | 100% (20/20) | 80% (4/5) | 68.0 MB |

生成 PDF 本身耗时：500 页命中缓存；5,000 页 1.94 s。

原始结果：`benchmarks/results/summary-*.json`（每次运行生成一个带时间戳的文件）。

## 解读与限制

- 索引速度主要受 pdfplumber 逐页坐标提取限制，约 105–116 页/秒；纯文本 PDF 会更快，扫描件还需 OCR（未测）。
- 专题 Recall@5 = 4/5 是关键词召回在高度重复的合成语料上的结果；未配置向量与精排时，语义相近但字面不同的查询召回会明显下降。
- 标记 Top-1 = 20/20 说明页码定位与“当前版本”过滤在索引规模增长后仍正确。
- 未测试 L（5 万页）/XL（20 万页）；未测试真实天津教材/真题；未测试 Embedding/Reranker/LLM 的吞吐与费用。
- 真实模型质量（Recall、NDCG、引用准确性、成果覆盖）**尚无实测数据**，不作承诺。

## 可复现命令

```bash
uv run python benchmarks/run_benchmark.py --pages 500 5000
```

数据写入 `benchmarks/results/pages-<n>/`，可删除后重跑。
