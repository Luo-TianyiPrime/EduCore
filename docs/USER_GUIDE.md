# EduCore 使用指南

EduCore 是一个**本地运行**的教育资料处理工具：导入自己的教材、试卷和教研文件，
建立索引，由 Agent 完成检索、阅读与分析，生成可编辑的教学文档。它不是教务系统，
也不内置课程、题库或学科重点。

---

## 1. 安装与启动

### 正式构建（Windows）

- 解压 `EduCore` 目录后运行 `EduCore.exe`。
- 程序会在 `127.0.0.1` 上选择可用端口，自动打开浏览器。关闭浏览器标签**不会**停止服务。
- 退出：系统设置 → 存储与凭据 → 「退出 EduCore 服务」。
- 数据目录默认 `%LOCALAPPDATA%\EduCore\EduCore-Data`。

### 开发运行

```bash
uv sync --all-extras
cd frontend && npm install && npm run build && cd ..
uv run python -m backend.main --port 8765 --open-browser
```

macOS 构建与签名状态见 `IMPLEMENTATION_STATUS.md`。

## 2. 首次配置模型

打开「系统设置 → 模型服务」，分别添加：

| 类型 | 用途 | 必填 |
|---|---|---|
| LLM | 任务规划、工具调用、分析生成 | 是（Agent 任务必需） |
| Embedding | 建立向量索引、语义召回 | 建议（否则仅关键词检索） |
| Reranker | 混合检索后的统一精排 | 建议 |
| OCR | 扫描页/图片识别 | 扫描资料必需 |
| VLM | 图表理解 | 可选 |

填写 Base URL、模型名与 API Key。OpenAI 兼容服务（DeepSeek、通义千问、SiliconFlow、
OpenAI 等）填到 `/v1` 层级；Reranker 与 OCR 填完整接口地址。

- API Key 存入操作系统凭据存储；设置文件只保存引用。
- 每个端点都可以「测试」：分别验证文本生成、工具调用、向量维度、精排结构或 OCR 结果。
- 「默认」单选决定新任务/新索引使用哪个模型。
- 更换 Embedding 不会自动重嵌入旧资料；旧索引保留，可在资料管理中按文件或文件夹「重建向量」。
- 更换 LLM/Reranker 不影响已有向量。

## 3. 添加资料

「资料管理 → 添加文件夹」：

- 使用「浏览…」打开系统目录选择器，或直接粘贴绝对路径。
- 递归扫描支持 `.pdf`、`.md`、`.markdown`、`.json`（OCR 结果）、图片格式。
- 原始文件只读引用，不会被复制或修改；移除资料只删除索引记录。
- 扫描完成后可查看解析状态：已就绪 / 需要 OCR / 失败 / 已移除。
- 修改、删除、重命名文件后再次扫描，检索只返回当前有效版本。
- 扫描件需先配置 OCR；单页可用「页面图像 → 识别本页」重新识别。

## 4. 知识检索

「知识检索」输入问题或关键词：

- 结果按向量与关键词分别召回，RRF 融合后由 Reranker 精排；未配置某项时会明确提示降级。
- 每条结果显示来源文档、章节路径、页码、检索名次与扩展上下文。
- 「查看原文」打开 PDF/图片页面，或文本上下文。
- 「检索详情」可查看各向量空间、候选数量、耗时与降级原因。

## 5. 创建任务

「AI 工作台」：

1. 选择资料范围（默认全部已索引文档；可多选）。
2. 选择模式：自动判断 / 精准检索 / 全量阅读 / 混合研究。
3. 输入自然语言任务，例如：
   - 「为所选教材生成教学大纲，安排 6 课时，标明重点难点」
   - 「整本阅读后提取全部试题，统计考点与分值」
   - 「比较教材与历年真题对同一主题的表述」
4. 点击「开始处理」。

任务创建时固定所选文档的**当前版本**，之后原文件更新不会改变任务证据。

### 任务中心

- 查看状态、批次覆盖、事件日志、模型调用与费用估算。
- 暂停：在批次边界停止派发新请求；继续：从检查点恢复，不重做已完成批次。
- 取消：立即中止；中断的任务在重启后可继续。
- 重试：失败批次或部分失败的任务可重试。
- 精准检索任务由 Agent 直接使用工具，不建立全量批次；暂停会在当前模型调用结束后生效。

## 6. 成果

任务完成后自动生成成果记录：

- 预览 Markdown 结构，支持直接编辑（保存为新版本）。
- 「局部重生成」只重写所选章节，其他章节保留。
- 「基础校验」自动检查标题/章节结构、引用能否在任务范围文档中匹配、任务要求的总分等可核对项；**内容正确性仍需人工审核**。
- 导出 Markdown / DOCX / JSON / PDF：
  - PDF 保留可搜索文本层，中文字体与分页已实测；
  - 可关闭打印稿中的显式引用；
  - 可选择自定义输出目录（绝对路径）。
- 版本历史保留每次编辑与局部重生成。

## 7. 数据、备份与隐私

| 内容 | 位置 |
|---|---|
| 配置（不含明文密钥） | 数据目录/config |
| 数据库、任务、成果 | 数据目录/database/educore.sqlite |
| 向量 | 数据目录/vectors |
| 解析/OCR/页面缓存 | 数据目录/cache |
| 任务笔记、检查点、草稿 | 数据目录/tasks |
| 导出文件 | 数据目录/artifacts（或指定目录） |
| 日志 | 数据目录/logs |

- 备份：退出应用后复制整个数据目录；原始资料仍在你自己的文件夹中。
- 网络：除你配置的模型服务外，不访问其他网络；无遥测、无云同步。
- 云端模型会收到相关文本或图像；本地服务失败时不会自动切换到未授权的外部服务。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 任务创建失败，提示未配置 LLM | 系统设置 → 模型服务添加并测试 LLM |
| 检索只返回关键词结果 | 未配置 Embedding，或文档未建立向量索引；查看「检索详情」 |
| 提示旧向量空间不可用 | 原模型被删除/更换；旧索引不参与向量检索，可「重建向量」 |
| 扫描件显示「需要 OCR」 | 配置 OCR 后重新索引，或在页面图像中识别本页 |
| PDF 导出失败 | 需要本机安装 Edge/Chrome；开发环境可执行 `playwright install chromium` |
| 维度不符 | Embedding 返回维度与配置不一致；清空维度让程序自动识别，或换正确模型 |
| 端口被占用 | 启动器会自动选择空闲端口；开发模式可改 `--port` |

## 9. 已知限制

- 尚无真实模型凭据下的完整验收数据；OCR 仅实现适配层与缓存，未接入真实服务实测。
- 复杂表格、公式与图表的保真度取决于原文件与模型能力；OCR 不等于图表理解。
- macOS 未在真机验收；Intel Mac 未列入支持范围。
- 大纲/教案/试卷等成果在缺少官方依据时属于 AI 建议稿，需教师审核。
